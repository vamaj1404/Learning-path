# Shells Overview — آشنایی با Shellها در امنیت سایبری

> بر اساس اتاق **Shells Overview** از TryHackMe در مسیر Cyber Security 101

## Shell چیست؟

به زبان ساده، **Shell واسطی برای تعامل با سیستم‌عامل** است. معمولاً وقتی از Shell صحبت می‌کنیم منظور محیط خط فرمان (CLI) است؛ مثل Bash در لینوکس یا PowerShell و CMD در ویندوز.

در امنیت سایبری، اصطلاح Shell اهمیت بیشتری پیدا می‌کند. وقتی مهاجم بتواند روی یک سیستم آسیب‌پذیر یک Shell به دست بیاورد، دیگر صرفاً یک آسیب‌پذیری پیدا نکرده؛ بلکه ممکن است بتواند **فرمان‌هایی را روی سیستم هدف اجرا کند**.

به همین دلیل Shell معمولاً یکی از مراحل مهم بعد از نفوذ اولیه است.

---

## Shell در حمله چه کاربردی دارد؟

داشتن Shell روی یک سیستم می‌تواند امکان فعالیت‌هایی مانند موارد زیر را فراهم کند:

* اجرای دستورات روی سیستم هدف
* بررسی فایل‌ها و اطلاعات سیستم
* شناسایی کاربران و سطح دسترسی آن‌ها
* تلاش برای **Privilege Escalation**
* دسترسی به سیستم‌های دیگر شبکه (**Pivoting**)
* جمع‌آوری یا انتقال اطلاعات
* ایجاد دسترسی مجدد و ماندگار
* انجام فعالیت‌های مختلف Post-Exploitation

بنابراین Shell را می‌توان نوعی **رابط عملیاتی مهاجم با سیستمِ به‌دست‌آمده** در نظر گرفت.

---

# انواع مهم Shell

در این مبحث سه مفهوم اصلی اهمیت دارند:

1. Reverse Shell
2. Bind Shell
3. Web Shell

تفاوت اصلی Reverse و Bind Shell در این است که **چه کسی اتصال شبکه را آغاز می‌کند**.

---

## Reverse Shell

در Reverse Shell، این **سیستم هدف است که اتصال را به سمت سیستم مهاجم برقرار می‌کند**.

تصور ساده:

```text
Attacker
   ↑
   │  Connection
   │
Target ───────────► Attacker
```

مهاجم معمولاً روی سیستم خودش منتظر یک اتصال می‌ماند و سیستم هدف پس از اجرای کد یا Payload مناسب، به آن متصل می‌شود.

### چرا Reverse Shell مهم است؟

یکی از دلایل محبوبیت آن این است که در بسیاری از شرایط، **اتصال خروجی از سیستم هدف راحت‌تر از اتصال ورودی به آن برقرار می‌شود**؛ برای مثال به دلیل وجود Firewall یا محدودیت‌های شبکه.

بنابراین در سناریویی که مهاجم نمی‌تواند مستقیماً به سیستم هدف متصل شود، Reverse Shell می‌تواند گزینهٔ مناسبی باشد.

### نقش Netcat

یکی از ابزارهای ساده و شناخته‌شده برای کار با Shellها **Netcat (`nc`)** است.

Netcat را می‌توان یک ابزار ساده برای برقراری ارتباط شبکه‌ای در نظر گرفت که در تمرین‌های Shell معمولاً برای ایجاد **Listener** یا دریافت اتصال استفاده می‌شود.

نکتهٔ مهم این است که لازم نیست در این مرحله تعداد زیادی دستور Netcat را حفظ کنیم؛ مفهوم اصلی این است:

> **Listener منتظر اتصال می‌ماند و Reverse Shell اتصال را به سمت آن برقرار می‌کند.**

---

# Bind Shell

در Bind Shell داستان برعکس است.

در این حالت، **سیستم هدف یک پورت را برای دریافت اتصال باز می‌کند** و مهاجم به آن پورت متصل می‌شود.

```text
Attacker ───────────► Target
                       │
                       │ Listening Port
                       ▼
                     Shell
```

بنابراین تفاوت کلیدی:

| نوع Shell     | آغازکنندهٔ اتصال  |
| ------------- | ----------------- |
| Reverse Shell | Target → Attacker |
| Bind Shell    | Attacker → Target |

### چرا این تفاوت مهم است؟

چون شرایط شبکه تعیین می‌کند کدام روش عملی‌تر باشد.

برای مثال اگر سیستم هدف اجازهٔ اتصال ورودی از اینترنت را ندهد، Bind Shell ممکن است به مشکل بخورد. در مقابل، اگر ارتباط خروجی از هدف امکان‌پذیر باشد، Reverse Shell می‌تواند مناسب‌تر باشد.

---

# Shell Listener چیست؟

برای دریافت یک Shell معمولاً به یک **Listener** نیاز داریم.

Listener برنامه یا سرویسی است که روی یک IP و Port منتظر اتصال می‌ماند.

به شکل مفهومی:

```text
Attacker

IP: X.X.X.X
Port: 443

      ↓
   Listener
      ↑
      │
      │ Reverse Connection
      │
    Target
```

در سناریوی Reverse Shell:

1. مهاجم Listener را اجرا می‌کند.
2. سیستم هدف یک اتصال خروجی ایجاد می‌کند.
3. Listener اتصال را دریافت می‌کند.
4. Shell در اختیار مهاجم قرار می‌گیرد.

پس:

> **Shell** محیط اجرای دستورات است،
> **Listener** منتظر اتصال است،
> و **Payload** چیزی است که برقراری Shell را ممکن می‌کند.

---

# Shell Payload چیست؟

Payload را می‌توان **بخشی از کد یا دستوری دانست که باعث ایجاد رفتار موردنظر می‌شود**.

در بحث Shell، Payload معمولاً کاری می‌کند که Shell از طریق شبکه در دسترس قرار بگیرد.

Payload بسته به شرایط می‌تواند با زبان‌ها و ابزارهای مختلفی ساخته شود؛ برای مثال:

* Bash
* Python
* PHP
* سایر زبان‌های اسکریپتی

در این بخش مهم‌تر از حفظ کردن دستورهای طولانی، درک این زنجیره است:

```text
Vulnerability
      ↓
Code Execution
      ↓
Shell Payload
      ↓
Network Connection
      ↓
Remote Shell
```

یعنی ممکن است ابتدا یک آسیب‌پذیری باعث اجرای کد شود و سپس از این توانایی برای ایجاد یک Shell استفاده شود.

---

# Web Shell

Web Shell کمی متفاوت است.

در اینجا مهاجم یک **اسکریپت روی Web Server** قرار می‌دهد که می‌تواند دستورات را از طریق خود Web Application اجرا کند.

مثلاً یک سرور PHP را در نظر بگیرید:

```text
Browser
   │
   │ HTTP Request
   ▼
Web Server
   │
   ▼
Web Shell
   │
   ▼
Operating System
```

در نتیجه مهاجم ممکن است بتواند از طریق یک درخواست HTTP باعث اجرای دستورات روی سیستم‌عامل شود.

### Web Shell چگونه ایجاد می‌شود؟

یکی از سناریوهای رایج، وجود آسیب‌پذیری در **File Upload** است.

اگر یک Web Application اجازه دهد کاربر فایل آپلود کند ولی نوع و محتوای فایل را به‌درستی بررسی نکند، مهاجم ممکن است بتواند یک فایل اسکریپتی مخرب را روی سرور قرار دهد.

به این نوع ضعف:

**Unrestricted File Upload**

گفته می‌شود.

بعد از قرار گرفتن Web Shell روی سرور، مهاجم می‌تواند از طریق Web Server با آن تعامل کند.

---

# تفاوت Web Shell با Reverse Shell

این دو مفهوم را نباید یکی دانست.

### Reverse Shell

ارتباط شبکه‌ای از سیستم هدف به سمت مهاجم برقرار می‌شود:

```text
Target ─────────► Attacker
```

و مهاجم معمولاً یک Shell تعاملی دریافت می‌کند.

### Web Shell

مهاجم از طریق Web Server با یک فایل یا Endpoint خاص تعامل می‌کند:

```text
Attacker
   │
   │ HTTP
   ▼
Web Server
   │
   ▼
Web Shell
   │
   ▼
OS Commands
```

بنابراین Web Shell بیشتر به **لایهٔ وب و اجرای دستورات از طریق Web Server** وابسته است.

---

# یک مدل ذهنی ساده

برای اینکه مطالب این اتاق را بهتر به هم وصل کنیم، می‌توان کل موضوع را این‌طور دید:

```text
             Initial Access
                   │
                   ▼
          Code Execution / RCE
                   │
                   ▼
             Obtain a Shell
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
     Reverse      Bind       Web
      Shell       Shell      Shell
        │          │          │
        └──────────┼──────────┘
                   ▼
            Post-Exploitation
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
     Explore   Privilege   Pivoting
     System    Escalation   Network
```

این مدل ذهنی از حفظ کردن ده‌ها Payload و دستور مهم‌تر است.

---

# ابزارهای مهم

در این اتاق ابزارهایی مثل **Netcat، Socat و زبان‌هایی مانند Bash/Python/PHP** در مثال‌ها مطرح می‌شوند.

اما بهتر است نقش هرکدام را بشناسیم، نه اینکه در مرحلهٔ اول همهٔ Syntax آن‌ها را حفظ کنیم.

| ابزار / مفهوم | نقش کلی                             |
| ------------- | ----------------------------------- |
| Shell         | تعامل با سیستم‌عامل                 |
| Netcat        | ارتباط شبکه‌ای و ایجاد Listener     |
| Socat         | ارتباطات شبکه‌ای پیشرفته‌تر         |
| Bash          | Shell و همچنین امکان اجرای Payload  |
| Python        | اجرای اسکریپت و ساخت ارتباطات       |
| PHP           | مهم در Web Shellهای روی سرورهای PHP |
| Listener      | منتظر دریافت Connection             |
| Payload       | ایجاد رفتار یا اتصال موردنظر        |

---

# نکتهٔ مهم امنیتی

Shell فقط یک ابزار مهاجمان نیست.

همین مفاهیم برای **Penetration Testing و دفاع سایبری** هم اهمیت دارند.

یک Pentester باید بداند:

* مهاجم چگونه Shell به دست می‌آورد؟
* Reverse و Bind Shell چه تفاوتی دارند؟
* Listener چه نقشی دارد؟
* Web Shell چگونه ممکن است روی سرور قرار بگیرد؟
* پس از به‌دست‌آمدن Shell چه فعالیت‌هایی ممکن است انجام شود؟

از طرف دیگر، یک مدافع باید بتواند نشانه‌های چنین فعالیت‌هایی را تشخیص دهد؛ مثلاً:

* Connectionهای غیرعادی
* Processهای مشکوک
* Web Shellهای ناشناس
* ارتباطات خروجی غیرمعمول
* اجرای Command از طریق Web Server
* ایجاد حساب یا دسترسی غیرمنتظره

---

# جمع‌بندی

مهم‌ترین چیزی که از مبحث **Shells Overview** باید یاد بگیری، مجموعه‌ای از دستورهای طولانی نیست؛ بلکه یک مدل ذهنی از نحوهٔ تبدیل یک نفوذ اولیه به دسترسی عملیاتی است.

**Shell** رابطی برای اجرای دستورات روی سیستم است.

**Reverse Shell** یعنی هدف به مهاجم متصل می‌شود.

**Bind Shell** یعنی هدف منتظر اتصال می‌ماند و مهاجم به آن متصل می‌شود.

**Listener** برنامه‌ای است که منتظر دریافت Connection می‌ماند.

**Payload** کد یا دستوری است که برقراری Shell یا رفتار موردنظر را ممکن می‌کند.

**Web Shell** اسکریپتی روی Web Server است که امکان اجرای دستورات از طریق سرویس وب را فراهم می‌کند.

در نهایت:

> **هدف این مبحث، فهمیدن مکانیزم ارتباط و مدل دسترسی است، نه حفظ کردن Payloadهای مختلف.**

اگر این مفاهیم را خوب متوجه شوید، یادگیری ابزارهایی مثل Netcat و روش‌های مختلف Shell در مراحل بعدی بسیار ساده‌تر خواهد شد.
